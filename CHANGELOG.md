# Changelog

All notable changes to Wienerdog. Format: [Keep a Changelog](https://keepachangelog.com), versioning: SemVer (0.x until the installed file layout stabilizes — ADR-0003).

## [0.14.0] — 2026-09-18

This release rebuilds both ends of the nightly memory consolidation: what it reads, and where it writes. On the reading side, it is now shown the conversation — what you asked for, the corrections you made, and the reply that closed each exchange — instead of all the machinery around it. A measurement across 187 real sessions found that more than half of what it had been told was you speaking was in fact control text one of the AI tools had written for itself. On the writing side, it no longer writes into your vault at all: a run works inside a private copy, and a separate step afterwards decides, note by note, what is allowed to land — so a night that goes wrong halfway leaves your notes untouched, and a file that tries to steer your future sessions can never get in. Around those two changes sits a lot of quieter work on a nightly job being honest about what it could not do: one unreadable session file used to end the entire night's run, a stuck lock could stop consolidation indefinitely without ever saying so, and a run that succeeded could still tell every session for the next day that it had failed. All three are fixed, and your vault now carries a standing, dated list of the sessions Wienerdog could not read. One known issue is written up at the end — the scrubbing of credentials out of Wienerdog's own job logs has measured gaps, and they are not fixed yet.

### Added
- **The nightly memory consolidation now reads your conversation, not your tools' output.** Each session used to be handed over whole: every tool result, every file that was read, every web page fetched, and every intermediate "working on it" reply. Measured across 187 real sessions, over half of the characters labelled as your own words were actually control text one of the AI tools had written for itself, and the model had no way to tell which half. It is now given the session's *primary dialogue* — your requests and corrections, plus the reply that concluded each exchange — and nothing else. The same sessions are still processed; what reaches the model is smaller and far more relevant, so the memories it proposes are about what you actually said rather than about the plumbing. None of the protection against planted instructions was traded away for this: where each message's content originally came from is still computed in code, from the full original session, before anything is dropped, and the model is handed that verdict rather than asked to work it out.
- **Your vault now keeps a standing list of the sessions Wienerdog could not read.** A new `reports/warnings.md`, written by Wienerdog itself and grouped by cause — the file is bigger than Wienerdog will read, it has too many lines, it could not be read at all, something inside it stopped Wienerdog reading it, or the notes made from it were withheld by the secret check too many times in a row. Because it lives in your vault, which keeps its own history, every change to it is a dated record you can look back through. Until now the only place a skipped session ever appeared was a banner inside your session context — something every `wienerdog sync` re-renders and almost nobody keeps a copy of.
- **The memory report now accounts for the sessions a run could not consolidate.** A new "Sessions this run could not consolidate" section gives an exact count for each cause: set aside by this run and skipped from now on, already being skipped and skipped again, too big to consolidate on their own, not reached because the run had already taken in as much as it could, not reached because it ran out of time preparing them, and passed over because the session was still being written. Each count says plainly when that session will be looked at again, and points at `reports/warnings.md` for the names. Before this, a night that consolidated three sessions and quietly passed over nine read exactly like a night that consolidated three.
- **`wienerdog doctor` now tells you how many session files are being skipped, and why.** One plain-language line per cause, with a pointer to the warnings file in your vault for the actual list. A healthy install says so outright: "no session transcripts are being skipped."
- **`wienerdog doctor` now tells you when the Wienerdog block in your `CLAUDE.md` or `AGENTS.md` has gone stale.** One line per AI tool you have installed: either the block matches the memory Wienerdog currently holds, or it is out of date and `wienerdog sync` brings it back in line. Staleness there used to be invisible until you noticed a session working from old information.

### Fixed
- **One unreadable session file no longer ends the whole night's run.** Four separate ways a single session file could crash the nightly run outright were measured — among them a crafted piece of text that breaks when Wienerdog tries to read it, and a session identifier long enough to defeat the filesystem. Any one of them aborted the entire run, every night, until someone found and deleted the offending file by hand. A session file whose preparation fails is now set aside with a reason recorded in `reports/warnings.md`, and the run carries on and consolidates every healthy session alongside it.
- **A stuck memory lock is now loud instead of silently stopping consolidation.** Only one nightly run may work at a time, and it takes a lock to say so. If a run died without releasing that lock, and its process number was later reused by some unrelated program, every later run saw "someone is still working," printed one line, and exited reporting success — so the job looked healthy, no alert ever fired, and memory consolidation simply stopped, indefinitely. A lock that is more than six hours past its own time limit now fails loudly, with an explanation of what may be holding it and what is safe to do about it, which means it reaches you the normal way: an alert, an email, and a banner in your session context.
- **Your sessions are no longer told the nightly job failed when it had just succeeded.** Seen in production on 2026-09-10: the 01:30 run failed and left a failure record, the 02:00 catch-up run succeeded — but the successful run rewrites your session context *before* anything can observe that it succeeded, so the fresh copy still carried "the dream job has failed." Nothing rewrites that file again until the next night, so every session for the following 24 hours was told a failure had happened that had in fact already been fixed. That final rewrite now leaves out its own job's earlier alerts — and only those. Another job's failure, a failure that is genuinely still unresolved, and a run that is not the scheduled job all still show exactly as before.
- **A night's reading budget is now spent on what actually gets read.** The limit on how much a run takes in was being counted against the raw size of each session file, before any of the filtering and scrubbing had happened — so content that was about to be discarded still reserved its share of the budget. In a measured case, extracts totalling 212,674 bytes were squeezed into 41,796, cutting one session down to 37 of its 200 messages; and because a shortened session is still recorded as done, the lost part was never retried. The budget is now counted against what is actually kept, so far more of your real conversation history survives into memory at the same configured limit.
- **Your own Goals and standing instructions are no longer cut off partway through, in every session.** The context Wienerdog assembles for each new session had a 120-line cap that real identity notes hit long before the separate size limit — so the most valuable, most deliberately written part of your notes was silently truncated every single time. The line cap is now 400, which puts the size limit back in charge, and an identity of a couple of hundred lines arrives whole.
- **Every new session no longer receives a second, identical copy of your memory.** Your `CLAUDE.md`/`AGENTS.md` already carries the memory Wienerdog wrote there, and a hook was pasting the very same text in again at the start of every session — two copies of up to 23 KB, every time, out of the same budget your actual work needs. The hook now checks first and stays quiet when the file already has it. If anything at all is uncertain — an unreadable file, an unexpected shape — it still sends the copy, so nothing is ever lost to this. Your `CLAUDE.md` itself is unchanged: same full text, still updated by `wienerdog sync`.
- **A broken install now explains itself instead of printing a stack trace.** If the installed program files went missing — a half-finished update, a purged temporary folder — every single `wienerdog` command, including the ones that would have told you what happened, died with a raw Node error. (This is not hypothetical: it hid a failure from the maintainer for four weeks.) The command now checks first and prints three plain lines naming what is missing and the one command that repairs it, `npx wienerdog@latest sync`. It deliberately does not suggest a plain `wienerdog sync`, which in that state is the broken thing.
- **The skipped-session banner is now a count that points at a file, and it stops repeating itself.** It used to list every affected filename inline in your session context and stay there permanently — on one real install that single line had grown to 16.8 KB, 73% of the whole context, and it never shrank as sessions closed. It is now a count plus a pointer to `reports/warnings.md`, and for the causes you cannot do anything about it retires from the banner after seven days. Nothing else retires: the sessions stay skipped, stay counted by `wienerdog doctor`, and stay listed in the warnings file, which never decays. The one class you *can* act on — notes withheld by the secret check too many times — still names its files and never decays.
- **A daily note Wienerdog cannot make sense of is now announced instead of silently dropped.** If the newest daily note's header was malformed or unclear about where its content came from, that day's summary just vanished from your session context with no explanation. Both cases now say so in the notice line at the top of the context.
- **Starting a session, and `wienerdog doctor`, can no longer hang or balloon on an odd file.** Both inspect your AI tools' configuration files, and both checked a file and then re-opened it to read — which meant a named pipe could hang the terminal indefinitely and a very large file could add hundreds of megabytes of memory (357 MB, measured). Both now read through the file they already opened, with a size bound. A permissions problem is also no longer read as "this AI tool isn't installed": the hook now sends your memory anyway, and doctor warns.
- **A failing job always leaves its record, even when Wienerdog cannot write its own bookkeeping.** At five points, a failure to write a job's status file — a full disk, a read-only folder — could escape before the durable "this job failed" record was written, so a failed job could go entirely unreported to you, to your digest, and to `wienerdog doctor`. The record is now written regardless, with wording that distinguishes the cases (including the awkward one where the work finished but could not be recorded, so it will run again).
- **The banners that mention a preserved copy no longer name a folder they cannot actually see.** When the secret check withholds a note, your original is kept aside for you — but which of two places it lands in is decided elsewhere, and the banners were naming one on a guess. They now point you at the memory report from the run that withheld it, which does know.
- **Content the secret check cannot read is kept for you again, instead of being thrown away.** When a note contains something Wienerdog cannot scan — binary content, or text it cannot round-trip — it is refused, which is correct. But that refusal had moved ahead of the step that saves your copy first, so the one class of content most likely to be worth a second look was the one class left with no copy and no notice. The check now happens inside the gate that preserves, so your original is kept aside and the review banner appears, as it does for everything else.
- **A withheld note is never destroyed just because saving your copy of it failed.** Of the three ways a note can be refused, only one enforced the rule that Wienerdog must never destroy the only copy; on the other two, a failed save returned a normal-looking refusal and the run carried on and cleaned up, taking the note with it. All three now stop the run outright if no verified copy exists, say which of the copies could not be saved, and keep the run's working area rather than deleting it, so the content is still recoverable. "Saved" is also now checked by reading the file back and comparing it, rather than trusted.
- **A saved copy now survives a crash.** Preservation reported success without ever asking the operating system to flush anything to disk, so a crash moments later could lose the copy it had just promised you. The file and the folders above it are now flushed before success is reported, and a failure to flush counts as a failure to preserve. The mirror case is closed too: when a preservation attempt fails partway and cleans up after itself, that removal is flushed as well, so a secret-bearing leftover cannot reappear after a crash.
- **Running Wienerdog from a git checkout no longer risks a spurious nightly failure.** On a development install, building a scheduled job's description hashed the entire checkout — thousands of files, half a second — purely to throw the result away, and a file changing mid-hash could make the next nightly run refuse to start. That hash is no longer computed there. Ordinary installs are unaffected and byte-identical.

### Security & hardening
- **The nightly memory consolidation no longer writes into your vault at all.** It used to write straight into your real notes and then have a separate pass try to catch anything it should not have written — a pass that could be blinded, for instance by the run writing a rule that hid its own new file from the check. A run now works inside a private, disposable copy of your vault, and a separate step afterwards decides note by note what may be copied across. If a run crashes or is killed halfway, your notes are untouched, because nothing it did was ever in them. Undoing a night's work is now `git reset` followed by `git revert <sha>` rather than a single command, since a merge can leave conflict markers that need clearing first — the documentation has been corrected to say so.
- **A note now reaches your vault by being allowed in, not by failing to be blocked.** The old check listed dangerous filenames to refuse. The new one lists the places a note is permitted to land, judges the file that would actually be written rather than the name it was handed, and refuses everything else — which is what makes it structurally impossible for a run to leave behind an instruction file that quietly steers your later sessions. The names it refuses outright grew from four to nine, covering the instruction files of other AI tools too (`AGENT.md`, `GEMINI.md`, `QWEN.md`, `WARP.md`, `replit.md`), backed by a dated inventory that has to be rechecked every release; and any folder whose name starts with a dot is now refused as a whole class, rather than the two that happened to be listed.
- **Every write into your vault now decides on the file it would really land on.** A single place does all of them. It resolves the destination first — a folder that is really a link somewhere else resolves to where it points — and judges *that*; it refuses to write onto or through a link; it publishes so a reader never catches a half-written file; and it abandons the write if the target stopped holding the bytes the decision was made against.
- **A note you edited during the night is never overwritten by the one the run wrote.** Where the two versions combine cleanly they are merged; where they conflict, your copy stays and the run's is refused and reported. The run's report is itself now treated as an ordinary note that has to pass the same checks — with a guarantee that, even if the report cannot be published for any reason, the record of what was and was not allowed in still reaches you.
- **The nightly run's git commands now run in an environment Wienerdog builds itself, one key at a time.** They used to inherit whatever the surrounding environment happened to hold, and a leftover git setting there could redirect the run's commit into a completely different repository, corrupt your vault's history, or trigger code of someone else's choosing — none of it involving you typing a git command. Only a small named list is passed through now. Your own git configuration and hooks still apply, because your home directory is deliberately on that list; everything else is dropped. The check that asks "is this vault a git repository at all" uses the same constructed environment, so it cannot be fooled into approving a folder that is not one.
- **A routine can no longer choose who a draft email is addressed to.** The inbox-triage and weekly-review routines shared one drafting tool that took whatever address the model typed, with no check at all — and inbox triage reads mail sent to you by strangers, which is exactly the input a prompt-injection attack arrives on. That tool is gone. In its place are two that take no address field: the weekly review's draft always goes to your own account, resolved from Google rather than typed; and an inbox-triage draft goes to whoever the message being replied to names, derived from that message's own headers. Neither routine can send anything, as before — you still review and send every draft yourself. (Narrower, not airtight: someone can still set the reply address on mail they send you, so a draft can still be aimed somewhere unexpected. You see it before it goes.)
- **What the morning digest and weekly review can read out of your vault is now filtered the way your session context already was.** These routines get a copy of parts of your vault, and that copy was taken with no checks at all, while the near-identical path feeding your sessions had three. It now skips a file that is not valid text, skips a file with a credential in it, and skips a daily note whose header is malformed or marks it as coming from outside the conversation — and the routine's own instructions now say to treat what it reads as information, not orders. This matters because these are the routines that can draft and send mail.
- **A folder name in your vault can no longer forge a section of your session context.** The "Active projects" list was built from your vault's folder names with no filtering, so anything able to create a folder — which needs no approval from you — could name it so that the list broke apart and a convincing fake "Standing instructions" heading appeared above your real ones. Folder names are now sanitized so one folder can only ever occupy one line.
- **A failing job's alert line can no longer forge a heading in your session context either.** The "this job failed" callout pasted stored text — job name, failure reason, log location — straight into the most instruction-adjacent part of the context, where a line break could manufacture a fake heading and a long enough run of them could push your real content out entirely. All four fields are now escaped, and a field too long for its budget is replaced wholesale rather than cut, so the callout is always exactly one line per failing job.
- **Every line of the daily summary now carries its own marker.** The summary was wrapped in an opening and a closing marker saying "treat this as information, not instructions" — and your daily notes can pull in text from mail and web pages during the day, so a line that reproduced the closing marker could make everything after it look like it sat outside the fence. Each line is now marked individually and there is no closing marker left to imitate.
- **Nothing running against a redirected home can touch your real scheduled jobs.** Scheduled jobs on macOS, Linux and Windows are keyed to your user account, not to a folder — so a test or development run pointed at a throwaway folder still reached the real ones. It did: a smoke test removed the maintainer's own nightly jobs. Touching the real scheduler now requires either that the run's folder is your real home or a deliberate opt-in, and `wienerdog uninstall` checks what is actually registered before deleting anything. Ordinary installs behave exactly as before.
- **Wienerdog's own private files stay private after a nightly run.** Three files under `~/.wienerdog` were rewritten in a way that recreated them at the system default permissions — so a nightly job quietly undid the tightening `wienerdog sync` had just done, every night. They now go through the same writer everything else uses, which pins them to your account alone regardless of your system settings, and closes a link-swapping hazard on the same path.
- **A malformed note header is now refused outright wherever identity and skills are decided.** The strictest tier of memory — the notes that describe you, and your skills — compared only the header fields it recognized, so a header with junk in it could still clear the bar and be written. Five decision points now refuse a malformed header before comparing anything.
- **The record that authorizes rewriting one of your skills is now parsed strictly.** That record decides the highest-trust write Wienerdog can make. It used to accept almost any spelling of true and false, could be confused by a specially named heading, and did not notice duplicate entries. It is now three-state and fails closed on anything it cannot read cleanly, refuses duplicates, and is immune to the naming trick.
- **Reading a file to inspect it now bounds what it reads.** The copy taken for the routines checked a file's size and type and then re-opened it, so a file swapped or grown in between slipped past those limits. It now opens once, decides on what it opened, and stops at the limit.
- **Test and process hardening.** The test suites now run under a single temporary root that is cleaned up afterwards (they were leaking roughly 1,676 directories per run, once reaching over half a million); a new proof runner mechanically checks that a test actually fails when the behaviour it claims to check is broken, after more than ten tests were found passing regardless; the install smoke script refuses to run against a machine with live scheduled jobs; and the guard that keeps the nightly job away from your real git index had two blind spots closed. No user-facing effect — this only tightens our own testing.

### Known issues
- **Known issue: a credential printed by a scheduled job can survive Wienerdog's scrubbing and sit in that job's own log.** Wienerdog scrubs credential-shaped text out of what it writes to disk. Measured in this release, that scrubbing has seven gaps, all of them in Wienerdog's own records of a run, and none of them is fixed yet. Four are the serious ones: a job's output is scrubbed as it arrives, one chunk at a time, so a credential that happens to be split across two chunks is never seen whole by the scrubber — and both halves are then written out back to back, which means the complete credential ends up in `~/.wienerdog/logs/dream/<date>.log` or `~/.wienerdog/logs/<job>/<date>.log`, contiguous and byte for byte. The other three are milder: a stored value is shortened to 2,000 characters *before* it is scanned, so a credential straddling that cut can leave a short head — up to 24 characters — behind in `state/alerts.jsonl` or `state/run-evidence.jsonl`. Every one of these files belongs to Wienerdog, sits on your own machine, and is readable only by your own account (mode 0600 inside a 0700 folder), so nothing here sends anything anywhere — but a credential in plaintext in a local log is still a credential in plaintext, so treat those logs as sensitive and read one before you attach it to a bug report. All seven are now pinned by tests so they cannot quietly regress or be declared fixed without being fixed; the repair is not written yet.

## [0.13.0] — 2026-08-03

This release is about earning trust before acting on it. Uninstall used to take its own bookkeeping (the install manifest) at its word when deciding what to delete; now, for both a managed block's spacing and a skill symlink, it first proves the thing in front of it is still the exact thing Wienerdog put there — and where it can't prove that, it leaves it alone rather than guess. A new owner-ratified rule, ADR-0038, names the principle behind every one of these changes: a new piece of manifest evidence may only ever narrow what an uninstall deletes, never widen it. The scheduler side gets the same discipline in reverse — registering a job now checks what your OS actually kept, not just what Wienerdog asked it to keep, and a scheduled job's path to Node now survives a Node upgrade instead of quietly breaking after one. Alongside all of that, `wienerdog alerts` gains an attended way to quiet the alerts you've already read.

### Added
- **`wienerdog alerts` and `wienerdog alerts ack`.** A job failure already showed up as a plain-language banner in your digest and as a durable record in `state/alerts.jsonl` — but there was no way to see the full list on demand, or to stop a job you're already aware of from repeating itself in your digest every day. `wienerdog alerts` now lists every alert on file, and `wienerdog alerts ack` lets you attendedly mark the ones you've already seen as acknowledged — a typed confirmation at a real terminal, not a flag you can script around. It changes nothing about the job itself: it still refuses, still exits non-zero, and still keeps its record. Acknowledgements for a job clear themselves automatically the next time it succeeds.

### Fixed
- **Uninstalling a managed block no longer eats into your own text.** The block Wienerdog owns inside your `CLAUDE.md`/`AGENTS.md` carries a blank line of spacing on each side, which uninstall is supposed to remove along with the block. Two ways that bookkeeping could go wrong are now fixed: uninstall could remove one blank line more than it ever added, or — where a block sat between two of your own lines — run those lines together into one. Uninstall now only ever removes the exact spacing it recorded adding, never yours.
- **`brew upgrade node` no longer silently breaks your nightly jobs.** Scheduled jobs (the nightly dream, routines) are registered with an absolute path to the Node binary that ran the installer. On a Homebrew install, that path lives inside a specific version's folder — the kind `brew upgrade node` removes — so upgrading Node could quietly strand every scheduled job pointed at a path that no longer existed. Registration now prefers a path that survives the upgrade (Homebrew's own alias, and only once it's confirmed to point at the exact same binary), so a nightly dream doesn't need re-registering every time Node moves.

### Security & hardening
- **Uninstall only removes a skill symlink it can prove is still the one it created.** It used to unlink any symlink recorded at a given path, with no check on what that link actually pointed to. It now confirms the link still resolves to the source Wienerdog recorded before touching it; a link that's been repointed, or that no longer resolves, is left alone.
- **That proof no longer accepts a recorded destination on faith.** The same check used to also pass a link if its raw, unresolved text matched the recorded destination — a comparison a forged manifest entry could satisfy without the link resolving anywhere real. That path is gone; only the resolved, on-disk destination counts now. A new rule, ADR-0038 ("a new manifest field may only narrow a deletion, never widen one") is now written down and ratified — it's the principle this change and the two below both follow.
- **Uninstall proves a managed block hasn't moved before trimming its spacing.** Wienerdog now records, at install time, exactly where a managed block's spacing was inserted, and checks that position still holds before stripping it. Previously, relocating a managed block within your own file could still cost you a blank line that was yours, not Wienerdog's; that case is now closed.
- **A skill symlink now carries proof of who created it.** Alongside the destination it points to, Wienerdog records a symlink's origin and file identity at the moment it's created, and checks that identity before removing anything. A link you've since adopted or replaced, or one that no longer matches what was recorded, is preserved rather than guessed at.
- **A failing job's alert or email body can no longer be shaped by what the job was processing.** The text in a fail-loud alert or email is now built only from fields Wienerdog itself controls — job name, failure code, timing details — never from the raw, untrusted content a job happened to be handling when it failed.
- **Registering a scheduled job now checks what your OS actually kept, not just what Wienerdog asked it to keep.** After writing a job into launchd or systemd, Wienerdog reads the registration back and confirms it matches; where it doesn't, Wienerdog retries by replacing that one entry — rolling back if the replacement doesn't hold either — and never touches jobs that were already registered correctly.

## [0.12.0] — 2026-07-28

This release rebuilds the nightly memory consolidation's secret fence around a measured distinction: a real credential is random *within* a segment, while a file path or digest is random only *across* segments. The scanner no longer mistakes the identifiers technical notes are full of for credentials, and when it does flag a lone suspicious snippet, it now scrubs just that snippet instead of withholding the whole note.

### Fixed
- **Notes full of technical identifiers are no longer withheld wholesale as suspected secrets.** The scanner used to treat any long random-looking run of characters as a potential credential, so file paths, `sha256:` digests, git commit ids, and document ids — exactly what technical notes contain — routinely got a night's note reverted. The detector now separates credential-shaped runs from path-shaped ones and only escalates a path-shaped run when the text right before it reads like a secret being assigned (a keyword followed by `:` or `=`). Measured on a real vault, this took the false-alarm rate from over a hundred wrongly reverted notes to a single withheld one — and that one was a deliberately planted key-shaped example, i.e. a correct catch.

### Security & hardening
- **A suspicious snippet now costs a snippet, not the note.** When the scanner flags a random-looking run that has no credential context around it, the nightly consolidation now scrubs just that run in place (`[REDACTED:…]`) and keeps the rest of the note, instead of reverting the whole note. Before scrubbing, the exact pre-scrub original is preserved under `state/quarantine/redacted/` — local-only, private to your account, never committed anywhere, and capped at the most recent 50 — so a wrong redaction is always recoverable. Redactions are listed in the nightly report rather than raising an alert banner, since no action is needed to keep the note.
- **Every named credential pattern now withholds the note for review.** Matches against the labelled provider rules (AWS keys, private-key blocks, bearer tokens, and the rest) are uniformly treated as hard findings that withhold the note — the scrub-in-place path is reserved for context-free random-looking runs, never for something that matches a known credential format.

## [0.11.0] — 2026-07-27

This release continues 0.10.0's audit arc, closing four more ways Wienerdog's own scheduled-job machinery could be misled by a write into its own folders: the decision to run in "production" (strict checks) versus "developer mode" (relaxed), the health check's idea of what counts as a healthy job, the advice printed when a run refuses to start, and what a re-sync re-publishes. Alongside that, the nightly memory consolidation is gentler on a false alarm — a suspected secret now delays a night's memories instead of erasing them.

### Fixed
- **A wrongly-flagged secret no longer costs you a night's memories.** When the nightly memory consolidation's secret scanner reverts a note as a precaution, the sessions behind it are now deferred and retried on later nights (up to three tries, then quarantined with a visible notice) instead of being marked done and lost for good.
- **The nightly memory consolidation starts reliably again.** A Claude Code update changed how its start signal gets interpreted, which could make a run silently do nothing. It now starts from a plain instruction instead, and checks that the run actually did something before calling it a success.
- **Scheduled jobs on macOS authenticate reliably again.** A Claude Code update moved sign-in into the macOS Keychain, but the deliberately minimal environment Wienerdog builds for scheduled jobs was unintentionally telling Claude to ignore the Keychain — even on an ordinary install using your real home folder. Nightly runs and routines no longer fail to authenticate because of this.

### Security & hardening
- **Whether an install runs in production or developer mode can no longer be forged by writing a file into Wienerdog's own folder.** That choice is now derived from where the install actually lives on disk — a structural fact a data write can't produce — instead of a marker file or an environment variable (`WIENERDOG_DEV`, now removed entirely). Previously, planting one file into a production install could quietly downgrade it to developer mode's relaxed checks.
- **The health check now verifies the scheduled job that's actually loaded, not just that one is registered.** `wienerdog doctor` — and the self-heal it triggers — now confirms the loaded entry still points at Wienerdog's own launcher and program, catching a swapped or stale entry that "something is registered" used to wave through as healthy.
- **The advice printed when a scheduled run refuses to start is now chosen from what was actually found wrong.** If Wienerdog's own program files look tampered with, it no longer tells you to run `wienerdog sync` — doing so would re-copy the install from the very files in question. It now tells you to reinstall from the registry (`npx wienerdog@latest sync`) instead.
- **Re-syncing an install no longer re-publishes its own launcher from the tree it's re-vendoring.** `wienerdog sync` now carries the existing, independently verified launcher forward untouched. If it's missing or unreadable, sync fails loudly with recovery steps instead of quietly rebuilding it from the tree it's supposed to be checking.
- **Test infrastructure hardening.** The automated test harnesses now read back what the OS scheduler actually has loaded and fail loudly if a test ever leaks a real scheduled entry onto a developer's machine, plus assorted macOS/Linux CI portability fixes and a live-proof harness repair. No user-facing effect — this only tightens our own testing.

## [0.10.0] — 2026-07-22

This is Wienerdog's biggest security release yet. Between 0.9.0 and this release, an independent audit went through every place Wienerdog reaches outside your own machine — connecting Google, the scheduled routines (morning digest, inbox triage, weekly review), the daily summary injected into every new session, and the nightly memory consolidation's ability to edit your identity notes — and found real gaps in each one. Every one of those capabilities was rebuilt and hardened before being turned back on. The result is the same conveniences as before, now running on narrower Google permissions, inside a locked-down execution environment that checks itself before every run, and with a human always confirming anything sensitive before it's trusted or sent.

### Added
- **Google access is now split into narrow, single-purpose permissions instead of one bundled key.** Reading your mail and calendar, drafting a reply, sending, and adding a calendar event each use their own separate, minimal permission — so a bug, or a hostile email a routine reads, can't quietly upgrade "read your inbox" into "send from your account." Scheduled routines never hold any of these permissions directly: they reach Google only through a small, temporary go-between that alone holds the credentials and will only perform a short, fixed list of allowed actions for exactly as long as the routine runs — never a broad, send-capable connection. The digest routine's own outgoing mail can only ever go to your own address, never one supplied by something it read.
- **Scheduled routines now run in a locked-down copy of Claude, checked fresh before every single run.** The morning digest, inbox triage, and weekly review already ran with a restricted toolset and no general internet or command-line access; now, right before each run, Wienerdog does a quick live check that the lockdown is actually holding on your installed version of Claude Code — and refuses to run rather than proceed on an unverified setup. This matters because a routine's whole job is to read things you didn't write (your inbox); the lockdown is what keeps a poisoned email from doing anything beyond being read.
- **The daily summary injected into every new session is now clearly labeled as background information, not instructions.** Your daily notes can pull in text from emails and other sources during the day, so the summary Wienerdog shows at the start of a session is now wrapped in a visible marker telling the model to treat it as data for context only — and it's read with a size limit, so an oversized note can't be used to overload a session either.
- **Automatic identity memory is back — safe, and always with your sign-off.** The nightly memory consolidation can once again propose edits to your identity notes (who you are, your preferences, your goals) after noticing the same pattern across enough sessions. But nothing it proposes is trusted into your next session until you approve the exact text with `wienerdog memory approve <file>`. New: `wienerdog memory approve --all` lets you review and ratify every note that's waiting on you in one sitting, instead of one at a time.

### Fixed
- **Sending your own morning digest, and the "something went wrong" alert email, now work under the new narrower send permission.** A Google quirk meant looking up your own address needed a slightly broader permission than sending does. Wienerdog now looks up your address using the read permission and sends using the narrower send-only one, so nothing had to give up its minimal-permission guarantee to keep working.
- **Scheduled routines keep working on the newest Claude Code.** A recent Claude Code update changed how it interprets a routine's start signal, which could make a routine silently do nothing. Routines now start with a plain instruction instead of that signal, so they're unaffected by the change.

### Security & hardening
- **Wienerdog now checks its own scheduled jobs, launcher, and installed program for tampering before anything runs.** Every scheduled and nightly run verifies that the code about to execute, and the job description driving it, still match what was actually set up — so a stray write into Wienerdog's own folder can no longer quietly swap in different code, or a different command, for the scheduler to run later.
- **Uninstall no longer trusts its own bookkeeping file blindly.** The record Wienerdog keeps of what it created is now treated as untrusted input when reversing an install: a corrupted or tampered copy of that record can no longer be used to delete or rewrite a file it shouldn't, and one bad entry in it no longer aborts the whole uninstall.
- **A killed or crashed job can no longer leave stray processes running.** Wienerdog still runs nothing in the background by design — but a scheduled routine or the nightly consolidation could occasionally leave an orphaned process behind if it was interrupted at just the wrong moment. Every run now hunts down and stops anything it started, including processes that tried to detach from their parent to survive.
- **Your private files stay private even under unusual filesystem tricks.** The checks that keep Wienerdog's secrets and configuration locked to your account alone are now resistant to symlink and path-swapping tricks that could otherwise have exposed or corrupted them.

## [0.9.0] — 2026-07-16

This release exists because Wienerdog's own health check failed its maintainer. A demo recording accidentally ran the installer "half-sandboxed" — its own folder redirected to a temporary location, but the real Claude Code settings left in place. The install quietly rewired the live setup to point at that temporary folder; three days later macOS purged it, every `/wienerdog-*` command vanished, session hooks failed on every start, and `wienerdog doctor` said everything was fine. All three gaps are now closed — and the new checks proved themselves immediately by finding a piece of that incident's residue the manual cleanup had missed.

### Added
- **`doctor` now verifies your skills are truly wired up, not just present.** For both Claude Code and Codex, every skill registration must point into the current install and contain its skill file. A link pointing at a vanished or foreign location, a leftover empty folder, or a damaged install copy gets a clear warning naming the skill and the fix (`wienerdog sync`). Previously, a completely broken setup could show all-green.
- **`doctor` now spots leftover session hooks.** A hook that matches Wienerdog's exact shape but whose script no longer exists — the thing that silently logs "hook failed" at every session start, forever — is flagged with the exact settings file and entry to remove. Notice-only: doctor never edits your settings, because a hook at a foreign path can't be proven to be Wienerdog's own.
- **`init` and `sync` warn about a half-sandbox before writing anything.** If `WIENERDOG_HOME` points somewhere custom while your real Claude Code or Codex settings would still be modified, you now get a loud warning naming the exposed tool — with stronger wording when the custom location looks temporary. It warns and never blocks, so deliberate custom setups keep working.

### Changed
- **`sync` decides which AI tools to write into once per run.** It takes a single snapshot of which tools are present, warns from that snapshot, and rechecks each tool still exists at the last moment before writing into it. A tool appearing or disappearing mid-run can no longer be written into without warning or crash the run partway through.

## [0.8.1] — 2026-07-13

This release fixes a dead-end that could hit anyone who connected Google before July 4 and then updated: the Google connection itself was fine, but every Gmail, Calendar, and Drive command failed with a message wrongly telling you to set Google up again.

### Fixed
- **Your Google connection heals itself after an update.** If Wienerdog finds your Google sign-in intact but its Google client library missing (the state older installs land in after updating), any Google command now offers to install the library on the spot — one consent, no browser, no re-connecting. Scheduled jobs that can't ask (like the morning digest) fail with a short, accurate note naming the one command to run, instead of the misleading "Google isn't set up yet."
- **Error messages about Google now tell the truth.** Wienerdog distinguishes "not connected," "connected but the library needs its one-time install," "the library is installed but damaged" (with the exact repair: delete its folder, then reinstall — a plain reinstall can falsely report "up to date"), and "your sign-in file looks damaged" — and never sends you back through full Google setup when you don't need it.
- **Pressing Enter at the install prompt now means Yes**, as its `[Y/n]` wording always claimed. (It had silently counted as No since the prompt was introduced.)
- **`--json` output stays clean JSON.** Install notices, consent prompts, and installer output go to the error stream, so piping a Google command's JSON into another tool can't be corrupted mid-install.
- The suggested repair command now works for folder paths containing spaces (the path is quoted).

### Added
- **`wienerdog doctor` now checks your Google connection.** One line tells you whether Google is connected and whether its library is healthy, missing, or damaged — with the exact remedy. Doctor stays silent if you never connected Google, and it validates the sign-in file itself instead of assuming any file means "connected."
- **Updates repair the library for you.** Running `wienerdog sync` (or an update) in a terminal offers the same one-time library install when your connection needs it — so machines that only run scheduled jobs get fixed the next time you touch them, without waiting for an interactive Google command.

### Security & hardening
- **Stronger containment for the on-demand Google library.** The check that trusts only the copy Wienerdog installed now constructs its path directly instead of searching upward — a copy of the library anywhere else on your machine is never even considered, and a subtle Node caching quirk can no longer make a freshly installed copy invisible until the next run.

## [0.8.0] — 2026-07-13

This release put Wienerdog's older, foundational parts through the same adversarial security review its newer features already get. Seventeen hardening changes came out of it. None of them change how Wienerdog works day to day — they close edge cases that would only matter if something (a downloaded file, a web page captured in a session recording, an interrupted uninstall) were hostile or malformed.

### Added
- **Connecting Google is more secure — and no longer hangs.** Google sign-in now uses PKCE and a one-time anti-forgery token (the industry standard for this kind of on-your-own-computer sign-in, RFC 8252), so another program sharing your machine can't slip into the handshake. And if you close the browser without finishing, sign-in now gives up after five minutes with a clear message instead of waiting forever.

### Security & hardening
- **Sending email stays inside the permission you granted — no header tricks.** A crafted subject line or contact name can no longer smuggle an extra, hidden recipient past the send permission you approved. Send permissions are also confirmed correctly when Wienerdog is run non-interactively, and an empty recipient is never treated as "allowed."
- **An interrupted uninstall is always safe to run again.** If uninstall is stopped partway (a crash, a closed laptop), it now leaves things so that simply running it again finishes the job — and on that retry it can never delete a vault you keep inside Wienerdog's own folder.
- **Downloads and installs are verified before they're trusted.** The version Wienerdog vendors is unpacked through a containment check (no file can escape its folder via a crafted path or symlink), the macOS/Linux installer pins HTTPS and shows you the exact Node download it will run, and the Windows installer refuses any non-HTTPS Git download address.
- **The uninstaller's "your notes are yours" guard resists path trickery on macOS.** The check that stops uninstall from touching anything outside its own area now correctly handles symlinks, Apple's firmlinks, and Unicode/upper-lower-case variations of your home-folder path, so a lookalike path can't slip past it.
- **Scheduling handles awkward file paths and never fails silently.** Schedule files now correctly escape special characters in paths, and if the system scheduler refuses a change, Wienerdog says so plainly instead of reporting success it didn't achieve.
- **Assorted internal hardening.** Session recordings from Codex are now read with the same "anything that came from a tool or a web page is untrusted" rule that Claude sessions already use (some of that content was previously dropped); the nightly dream keeps its skill-usage bookkeeping correct even when a recording is trimmed for length; skill folders are refreshed by verified ownership instead of a blind delete; hook commands and memory "managed blocks" are written and matched more strictly; the secrets folder is locked down only if Wienerdog created it; and the internal alerts log can no longer grow without bound.

## [0.7.0] — 2026-07-12
