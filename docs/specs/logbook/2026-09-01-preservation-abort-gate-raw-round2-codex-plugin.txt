A read can be served from cache before either the file or directory entry is durable; after dream.js deletes the workspace, a crash can therefore lose both copies. The same snapshot can become stale if the artifact changes between read-back and teardown. “Same invocation” does not close either window and contradicts Q4’s requirement that a durable artifact hold the bytes before destruction.
  Recommendation: Require file and containing-directory durability before preservation succeeds—fsync the written file, rename, fsync the directory—and ensure the verified artifact remains the basis for teardown. If that guarantee is intentionally excluded, the WP cannot claim to enforce Q4 and must retain the workspace instead.
- [high] Materiality B — the closed discriminant contains an unreachable abort value (docs/specs/WP-preservation-abort-widening.md:304-307)

  Recommendation: Remove the unreachable value from the active Table P taxonomy and scope it as Q18 legacy history, or define a reachable abort condition and reconcile it with P3. Represent valid message inputs as a discriminated union, or validate discriminant/basename combinations at runtime.
