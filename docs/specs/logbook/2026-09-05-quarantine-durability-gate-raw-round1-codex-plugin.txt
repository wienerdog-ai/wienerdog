Findings:
- [high] [A] The flush set assumes pre-existing ancestors are already durable (docs/specs/WP-quarantine-preserve-durability.md:398-402)
  F0 requires every directory entry the artifact depends on, but F3 flushes ancestors only when this invocation's `mkdirSync(qdir)` created them. A reachable first-run path violates that assumption: shipped `acquireLock(stateDir)` can create `state/` earlier in the same run without flushing its parent; preservation then creates `quarantine/`, receives `firstCreated === qdir`, flushes `qdir` and `stateDir`, but never flushes the core directory containing the new `state/` entry. The preservation can therefore report success although an ancestor naming the whole quarantine subtree has no completed flush. Existing-but-unflushed quarantine ancestors left by an interrupted earlier operation have the same problem.
  Recommendation: Define a durable anchor and flush the complete ancestor chain needed to reach it on every successful preservation, or expand scope so creation of `stateDir` establishes that precondition. Add a test where `stateDir` was created earlier in the run and require its parent directory to be flushed.
- [high] [A] Path-based reopening can flush a different inode than the one read back (docs/specs/WP-quarantine-preserve-durability.md:399)
  The design closes `readFileSync(dest)` and later reopens the pathname for flushing. The stated dream lock does not prove exclusivity: shipped locks can be stolen after their deadline while the superseded process continues, and teardown explicitly handles that state. Two same-day runs can both pass the non-atomic destination collision check; one can replace `dest` between the other's read-back and `openSync`. That run then flushes the replacement inode and returns bytes read from the displaced inode. `O_NOFOLLOW` does not reject a regular-file replacement, and QPD-1's fd-to-path mapping still sees the expected pathname, so the criterion passes while the only-copy invariant can fail.
  Recommendation: Require an atomic no-clobber destination commit and bind byte verification and flushing to the same opened inode, with post-operation pathname/inode validation as appropriate. Add a deterministic interleaving test that replaces `dest` between verification and flush and requires failure rather than success.
- [high] [A] F3 flush failures are not part of the proof contract (docs/specs/WP-quarantine-preserve-durability.md:443-447)
  QPD-2 injects only an artifact-flush failure. QPD-4 merely observes that a created directory's parent appears among flushed paths. An implementation can call `flushOne(parent, true)` during the F3 walk but ignore its false result; all five identities and all prescribed mutations can still pass, yet an ancestor `openSync`/`fsyncSync` failure is followed by a successful preservation. That directly violates F4 and permits success without every required flush completing.
  Recommendation: Make QPD-2 exercise failures at F1, F2, and every observable F3 level on a fresh redacted tree, asserting `null`, D2 removal, and the existing abort for each. Add a RED mutation that specifically swallows the F3 walk's failure result.
