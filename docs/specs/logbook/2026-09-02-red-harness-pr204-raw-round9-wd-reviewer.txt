### The reporter, measured rather than accepted

Raw bytes on Node v25.9.0 (`|` marks line start, `$` line end):

```
|ok 1 - case $
|ok 2 - case$
|ok 3 -   padded  $
|ok 4 - skipped  # SKIP why$
|ok 5 - has  \#hash inside$
|ok 6 - trap  \# SKIP not-a-directive$
```

And the identities `parseTap` derives, JSON-quoted so whitespace is visible:

```
["case "]                          directive=null
["case"]                           directive=null      ← distinct, not collapsed
["  padded  "]                     directive=null
["skipped "]                       directive="SKIP"    ← name's space kept, separator consumed
["has  #hash inside"]              directive=null
["trap  # SKIP not-a-directive"]   directive=null      ← the greedy trap does NOT fire
```

Every claim holds: names keep their own leading and trailing whitespace, and TAP puts exactly **one** space before a directive.

**The greedy-separator attack the coordinator named comes back clean, and I checked why rather than just that.** A `#` inside a name is escaped by the reporter (`\#`), so the character before `#` is a backslash, not a space — `/ #\s+(SKIP|TODO)/` cannot match there. Even the deliberately adversarial name `trap  # SKIP not-a-directive` survives intact with `directive=null`.

The old regex's failure mode, isolated:

```
OLD  /\s+#\s+/   "skipped  # SKIP why"  ->  name "skipped"    ← eats the name's own space
NEW  / #\s+/                            ->  name "skipped "   ← correct
```
