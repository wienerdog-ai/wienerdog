FINDING 1 — C1's three clauses are not an exclusive partition of the actual slots

Affected files and lines: docs/specs/WP-show-slot-own-value-kind.md:315-320, 331-345; src/cli/dream.js:238-261, 1041-1043
Confidence: 0.98

What can go wrong:
The canonical rewrite can still classify an existing slot two different ways. Clause (1) says any slot holding "a value the run COMPUTED" is own; clauses (2) and (3) then divide "carried" tokens by position. But computed and
carried are not mutually exclusive properties in the actual pipeline. The run constructs the dynamic commit message at src/cli/dream.js:1041 and commitNamedSet carries it into commit-tree's -m slot at :259-261. The run also derives
mode from ls-tree/default data at :238-239 and carries it into update-index at :256. Both values are literally computed by this run, yet KNOWN_CALLS correctly leaves those slots FREE and the new rule intends clause (3) to govern
the -m argument.

Why vulnerable:
C2 supplies the narrower concept the partition needs—an object name git emitted as the whole stdout of a pinned producing shape—but C1 clause (1) does not use it. C1 instead retains the loose word "COMPUTED", while its own clause
(3) treats named-option arguments as carried. Thus the categories overlap before position is considered. The checklist shorthand at :333 repeats "computed -> own", so the ambiguity is scheduled to be copied into W1(c), the
canonical surface reviewers use to decide slot kinds.

Likely impact:
An implementer or later reviewer can follow clause (1), change commit-tree's message or update-index's mode to RUN_VALUE, and make legitimate dream runs fail because those values never join computed. Or they can preserve ANY and
leave W1(c) contradicting its executable mirror. Either outcome defeats the stated goal of making slot-by-slot review determinate and risks another silent slot-kind drift.

Concrete recommendation:
Rewrite clause (1) to reference C2's exact membership predicate, for example: "a slot carrying an own-value-set member—an object name git emitted as the whole stdout of an earlier pinned producing shape—is own." Then define clauses
(2) and (3) over every remaining argument value. Explicitly adjudicate shape (3)'s mode/path, shape (8)'s dynamic -m message, and shape (9)'s fixed -m message in C1 and mirror the same complete wording in the checklist and eventual
W1(c).

FINDING 2 — the source-form proof contradicts the Exact contract and can be spoofed

Affected file and lines: docs/specs/WP-show-slot-own-value-kind.md:273-284, 418-455, 474-490, 533-545
Confidence: 1.00

What can go wrong:

to occur zero times anywhere in tests/unit/dream-pipeline.test.js. Conversely, the three file-wide greps do not prove that the live KNOWN_CALLS entry is the literal. A literal-looking comment plus a multiline concatenated

Why vulnerable:
The positive grep is neither anchored nor scoped to the KNOWN_CALLS initializer, so comments and unrelated code satisfy it. The third grep assumes 'show', and WARNINGS_REL share one physical line, while JavaScript permits the
