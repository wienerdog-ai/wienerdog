  The prescribed success sequence flushes the artifact and `qdir` before `ownsName(dest, fd)`. The user's own hand can retain a spare hard link to the created inode, wait until `qdir` has been fsynced, unlink `dest`, and link the spare inode back at `dest` before the last gate. `lstat` then observes a regular file with the expected `(dev, ino)`, so the function returns SUCCESS, but the directory entry observed at that gate was created after the directory flush and has no completed flush covering it. A crash may therefore lose the returned name. This is not F10(i–iii), because no invocation removal is raced; not (iv), because the substitution precedes the last gate; not (v), because no bytes are overwritten; and not A12 under the spec's own classification, which expressly puts substitutions by the user's hand in scope. Thus the quoted closing statement still claims directory-entry durability beyond the prescribed sequence.
