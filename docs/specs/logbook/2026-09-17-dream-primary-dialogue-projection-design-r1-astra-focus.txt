Background: Wienerdog's nightly "dream" job parses Claude Code and Codex CLI session transcripts (src/core/transcripts/claude.js, codex.js, index.js) into extracts that one consolidation model turns into vault memory. Today the extract includes tool results, intermediate assistant progress and harness/developer instructions - measured on one install, more than half of what the model is told is "the user speaking" is Codex developer boilerplate mapped to role user. This spec adds an OPT-IN, deterministic, code-only projection, parsePrimaryWithOutcome, returning {extract, gateExtract, intakeBytes, parse}: `extract` is PRIMARY DIALOGUE only (genuine user requests/corrections plus their concluding assistant replies; tool calls, tool results, reasoning, intermediate progress and developer/system instructions excluded; subagent and sidechain sessions supply none); `gateExtract` is a text-free, code-only projection of the ORIGINAL capped timeline that preserves message roles and skill-invocation geometry for the authorization check in src/core/dream/validate.js; `intakeBytes` is the raw capped extract's size, so that admission against the byte budget is unchanged by construction. A conservative, never-resetting provenance flag derived_from_untrusted is computed over the original stream BEFORE projection. Existing parse/parseWithOutcome callers and golden fixtures must be unaffected. Challenge, EXECUTING the real parsers on synthetic transcripts where you can (never copy private transcript content anywhere): (1) PROVENANCE is the security property - can any path mark text derived from tool output, a web page, an email or a copied subagent history as derived_from_untrusted:false; does taint ever reset across a user turn, a dropped exchange, a cap boundary or a legacy-format fallback; is "verified primary user text" ever claimed for text the code cannot verify (the spec says a headless routine's prompt is indistinguishable from a human's and adds no heuristic - is that stated honestly); (2) ACCEPTANCE RULES: for Claude (non-meta, non-sidechain user records; assistant text on stop_reason end_turn; tool_use progress excluded; text blocks inside array-valued user content) and Codex (input_text blocks identified by the index-parallel content_item_kinds metadata; assistant output_text on phase final_answer; developer/system excluded; thread_source subagent excluded) - construct inputs that break each rule: misaligned or malformed metadata, metadata as a JSON string, a user message whose blocks mix kinds, an assistant reply with no stop reason, an unanswered request, interleaved tool results; does present-but-malformed metadata wrongly fall into a legacy fallback; (3) the gate projection: is its geometry provably identical to what validate.js's gate would compute from the ORIGINAL capped extract (indices NOT renumbered), and can it ever carry message text; (4) caps: the per-message character cap applied AFTER secret scanning and the newest-N message cap - is `truncated` truthful on the projected extract, and does intakeBytes really equal today's measured quantity byte for byte; (5) back-compat: are parse() and parseWithOutcome() and every golden fixture provably unchanged; (6) does each acceptance criterion and each RED-proof declaration discriminate (expectRed sets are marked "derived - the implementer measures and corrects" by design; say if a derived set is implausible); (7) do the file:line citations resolve on this tree. Report findings about PRODUCT or SECURITY behaviour in the main list; list verification-machinery findings separately, marked as machinery.
