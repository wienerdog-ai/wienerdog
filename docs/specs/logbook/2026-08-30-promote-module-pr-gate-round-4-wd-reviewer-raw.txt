**3. [contract] `docs/GLOSSARY.md:91-93` — the canonical `promotion` entry says there are "only three" outcomes and enumerates three that exclude `redacted`. Band: contract.**

That makes it the same "a number beside a list inside a cell" failure the sibling spec has already recorded three times (round 4's F-3, round 5's N2, round 6's COH-2).

This was not introduced in the fix window; it has been on the branch since the glossary entry was written and three rounds including mine missed it. Raising it now rather than after merge.

**Fix:** drop the count and add the fourth outcome, in the entry's plain-language register — e.g. "One outcome per changed path: the note is promoted as the dream wrote it; a merged version is promoted ...; **a scrubbed version is promoted, with the unredacted original kept aside for you** ; or it is refused and the reason is reported."

**4. [contract] `docs/GLOSSARY.md:101-102` — "the four quality gates judge the bytes that would actually land" is false for one of the four, and it is false in precisely the case the spec names as a residual. Band: contract.**

Measured in the code, not inferred: `promote.js:805-812` calls `gates.secret` with `afterBytes` (the brain's bytes) and `record.addedLineNumbers` — **before** the merge; `promote.js:942-975` calls `gates.skillBody`, `gates.tier3` and `gates.ledger` with `d.candidate`, the merged bytes. **Fix:** scope the sentence to the three — e.g. "Every promoted byte goes through a *vault write*. The skill-body, Tier-3 and ledger gates judge the bytes that would actually land, not an earlier draft of them; the secret scan judges what the dream itself wrote."

**5. [contract] SPEC FAULT — `date` is declared `date:string` with no shape, while two consumers use it as a path component. Route to wd-architect. Band: contract.**

The implementer's fix is the right call under `CLAUDE.md`'s ambiguity rule (choose the simpler option) and I am not asking for it to change. But the brief asked whether non-empty-string is the right strength, and the honest answer is that the spec does not say and cannot be read to say.

What is measured: the spec's `### Exact contracts` declares `date:string` (`:254`) and its prose says only "the run's date, which names the report `&lt;reports_dir&gt;/&lt;date&gt;.md` (Tables D and R)" (`:268-270`). So `date` is an unsanitized path component in the quarantine artifact name and in the report path, and neither this spec nor Table Q constrains it.

`typeof date === 'string' &amp;&amp; date !== ''` catches the caller bug the finding was about (`undefined` → `undefined-note.md`) and is consistent with the six siblings, which is the whole of what round 3 asked for. What it does not catch is a `date` carrying `/` or `..`, which reaches a filename the module does not build and cannot see. That is a contract gap, not an implementer's oversight — and it is not the implementer's to close by guessing a regex, because the shape has to agree with `WP-dream-promote-report`'s `&lt;reports_dir&gt;/&lt;date&gt;.md` and with the shipped gate's `YYYY-MM-DD`.

**Recommend:** route to wd-architect to decide whether `### Exact contracts` declares a shape for `date` (and, if so, whether the check is `/^\d{4}-\d{2}-\d{2}$/` or merely "no path separators"), and to say which table owns it.
