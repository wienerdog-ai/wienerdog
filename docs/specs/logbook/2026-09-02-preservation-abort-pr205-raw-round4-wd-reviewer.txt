The `writeFileSync(path, …)` seam the other fixtures patch is intact — which is why the suite is green rather than the 8 failures my first `openSync`-based candidate produced.

**I attacked the one seam the fix depends on: can a non-`EEXIST` errno arrive while a foreign file sits at `tmp`, causing that foreign file to be deleted as "owned"?** Tested against the real OS, no patching:

```
existing file + non-writable dir  -> errno = EEXIST   ← carve-out holds
NO file       + non-writable dir  -> errno = EACCES   ← nothing created
```

`O_CREAT|O_EXCL` returns `EEXIST` for an existing file *before* the directory permission check, so the carve-out cannot be bypassed by a permission error. And in the converse case — over-claiming ownership for a path the create never allocated — I confirmed it is a harmless no-op: `removeOwnedQuarantinePath` uses `force: true`, so `ret=null`, `dir=[]`, no spurious D3 throw. The fix is conservative in the safe direction and precise in the dangerous one.
