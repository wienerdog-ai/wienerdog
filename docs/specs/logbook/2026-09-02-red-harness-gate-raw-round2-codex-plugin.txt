Findings:
- [high] Mutation containment is vulnerable to a post-BASELINE symlink swap (docs/specs/WP-criterion-red-harness.md:210-217)
  Materiality A — SANDBOX canonicalises the mutation path before BASELINE, but BASELINE executes the suite before APPLY. The suite can replace the checked file with a symlink into the real checkout; APPLY and RESTORE can then follow it, transiently mutate the checkout, redden the sandboxed suite through that same link, restore the original bytes, and leave the criterion 7 git-status comparison unchanged. The three required escape cases exercise only pre-existing paths, so they do not close this check/use race. The writable node_modules symlink similarly has no mechanism enforcing the claimed “resolution-only” use.
  Recommendation: Require containment to be re-established atomically at every APPLY/RESTORE write—using no-follow descriptors or equivalent identity checks—and add a fixture whose BASELINE swaps the target to an outward symlink. Test or remove the claim that the dependency link cannot be written through, and mirror the corrected boundary into ADR-0042 before signature.
- [medium] The TAP invocation is unsupported on part of Node >=18 (docs/specs/WP-criterion-red-harness.md:243-250)
  Materiality B — the package supports every Node 18 release, but Table D unconditionally forwards --test-reporter=tap. Node’s official reporter history records that flag as added only in v18.15.0, so Node 18.0–18.14 reject the invocation before BASELINE. The “use whatever field the running Node emits” rule does not repair an option the runtime cannot parse, leaving the new lane unavailable on a supported installation. [Node test reporter history](https://nodejs.org/download/release/v22.17.0/docs/api/test.html#test-reporters)
  Recommendation: Either support pre-18.15 by using its default TAP output or explicitly raise the repository/runtime floor. Add an acceptance run on the oldest supported Node version and pin the assertion-versus-thrown-error diagnostics expected there.
