### The four P2s

**(1) Option-shaped suite paths — FIXED. I reproduced both the vulnerability and the hang.**

```
DASH path, no --      -> exit 0, ["1..0","# tests 0"]      ← the vacuous default-discovery pass
node --test -- '--test-name-pattern=target'  -> >>> TIMED OUT / HUNG (15s)
legal path WITH --    -> exit 0, tests run normally
--test-name-pattern=greeting WITH --  -> ok 1, 1..1   (identical without --)
```

So Decision 23 is **correct and measured**: `--` does not rescue a dash path — in the `--test-name-pattern=` shape it hangs, the one failure a runner cannot report — and the refusals are the real fix. The terminator is harmless for legal paths and does not break pattern forwarding, which I checked because adding `--` was a genuine regression risk.

Both directions end-to-end: dash suite → `ERROR exit=1`, *"suite" must not begin with "-"*; legal suite → `PROVEN exit=0`. The refusal granularity is exactly right, and it matters that the check runs on the **normalised** form:

```
"--test-name-pattern=x"  -> REFUSED   (node reads as option)
"-dash.js"               -> REFUSED   (node reads as option)
"./-dash.js"             -> REFUSED   (normaliseRel → "-dash.js", which IS dangerous downstream)
"tests/-dash.js"         -> accepted  (node does not read as option)
```

`M21`/`M22`-equivalents both kill 1.

**(2) Byte-faithful mutation — FIXED, verified at the byte level rather than by verdict.**

### The spawn-timeout residual — I judge it a residual, correctly

Four reasons, and I reached them before reading the PR's own note, which lands in the same place:

1. It is a **liveness** failure, never a soundness one — no false `PROVEN` is reachable through it.
2. A hang is **loud**: the developer sees nothing happen and interrupts, and the interrupted-run sandbox residual already covers the leftover directory. A wrong timeout is **silent** and produces a misleading `ERROR` that looks like a real finding — strictly worse.
3. There is **no principled value** available to the implementer. Table D carries the cost model (~15 s/run, ~90 s/lane) but no budget for a stuck child. Picking one would be expanding scope to resolve ambiguity, which CLAUDE.md forbids.
4. Suites are committed repo content; one that blocks forever hangs `npm test` too, so the lane is not uniquely exposed.

If the owner ever wants it closed, the mechanism is already there — `assertCompleteRun` reports a killed child as ERROR — so the only missing piece is the **budget**, which is a contract fact belonging in Table D beside the cost model. That is a spec amendment, not an implementer's guess. Recorded, not changed, is right.

Worth crediting separately: **Decision 26** — the `runSuite` refusal test had to move out of process because a synchronous `spawnSync` block cannot be interrupted by a test timeout, and *the mutation matrix is what surfaced it* (the first version hung the matrix rather than reporting `M22`). That is this WP's own method catching a defect in this WP's own tests.
