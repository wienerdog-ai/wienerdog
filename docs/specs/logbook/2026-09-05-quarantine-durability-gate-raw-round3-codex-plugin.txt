Findings:
- [high] Band A — the no-clobber commit still permits deletion of a post-commit replacement (docs/specs/WP-quarantine-preserve-durability.md:513-580)
  `linkSync(tmp, dest)` proves only that `dest` named this invocation’s inode when the link completed. F8 then requires opening `dest` later, after the temp removal. If the explicitly in-scope user restores or renames another file over `dest` during that interval, `openSync(dest)` binds to the replacement. When its bytes differ, the comparison short-circuits before `stillNamed`, `replaced` remains false, and the mandated D2 cleanup deletes the replacement. Thus F9 does not make F8’s non-disposal rule decidable across the stated sequence, violating the ownership contract and potentially deleting a user-restored artifact. QPD-5 cannot catch this: both substitutions are injected from inside the artifact flush, which occurs only after open/read/byte-compare succeeded. An implementation with this defect therefore passes the proposed criterion-6 evidence.
  Recommendation: Carry the committed inode’s identity independently of the later pathname open—for example, retain or stat the owned temp inode before linking—and authorize D2 removal only when the current `dest` still matches that identity. Add a QPD-5 case that substitutes `dest` after successful link but before the artifact open/read, asserting failure and byte-preservation of the replacement.
