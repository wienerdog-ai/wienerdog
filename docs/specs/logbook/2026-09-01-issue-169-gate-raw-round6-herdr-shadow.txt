  Scenario: The manifest is already absent before uninstall starts. The initial manifestLib.load converts ENOENT to an empty manifest, so
  disclosure and confirmation can occur. The post-confirm read then must abort on any missing manifest. Rerunning produces the identical
  sequence; even WIENERDOG_ALLOW_REAL_SCHEDULER=1 cannot help because comparison precedes clearance.

  Impact: An older, damaged, or partially removed installation can never be uninstalled through the CLI. The prescribed “rerun” message is
  false recovery guidance. This is distinct from the intended present→missing race.

  Recommendation: Capture manifest existence with the disclosed snapshot and distinguish transitions. Present→missing must abort. For
  absent→absent, either:

  - require an answered-CLEAN own-identifier probe before allowing empty-snapshot mechanics cleanup, bypassing the authority shortcut; or
  - refuse before confirmation with durable manual-recovery instructions.

  Add acceptance cases for absent→absent, present→absent, and absent→present.
