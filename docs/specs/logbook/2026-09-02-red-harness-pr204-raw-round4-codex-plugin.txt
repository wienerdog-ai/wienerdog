  When a valid repo-relative suite filename begins with `-` (for example a root file named `--test-name-pattern=target`), Node parses this argument as another option and default-discovers different tests. Because only the declared suite is protected from mutation, a proof can then mutate the actual discovered assertion host and incorrectly reach `PROVEN`. Pass an option terminator before the suite path and validate it as a regular file, as required by [Table A's suite/file rules](docs/specs/WP-criterion-red-harness.md#L181-L187).

- [P2] Preserve untouched bytes during mutation — /Users/gyulafeher/Documents/Claude_Projects/wienerdog-wt/criterion-red-harness/scripts/red-proofs.js:1047-1047
  If the target contains malformed UTF-8 bytes outside the matched substring, decoding with `'utf8'` replaces them with U+FFFD and the later string write re-encodes those replacements. `written === expected` still passes even though unrelated bytes changed, so a named assertion can redden from collateral corruption and be reported `PROVEN`. Mutate Buffers or reject files that do not round-trip exactly to satisfy [Table B row 4's byte-equality requirement](docs/specs/WP-criterion-red-harness.md#L291).

- [P2] Gate mode-dependent tests on the real host — /Users/gyulafeher/Documents/Claude_Projects/wienerdog-wt/criterion-red-harness/tests/unit/red-proofs.test.js:90-99

The tests expecting writes through 0500 parents to fail therefore receive no `EACCES` (for example the isolation, parent-write, and traversal cases), causing the newly added suite and hence `npm test` to fail in the environments this helper claims to support. Skip or privilege-drop the mode-dependent cases based on the real host instead of spoofing it, so [criterion 13](docs/specs/WP-criterion-red-harness.md#L894) remains true.
