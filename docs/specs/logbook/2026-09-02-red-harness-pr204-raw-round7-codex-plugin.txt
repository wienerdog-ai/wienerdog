# Codex Review

Target: branch diff against main

The runner can violate its source-tree isolation when the ambient temp directory is nested under the selected root, and an otherwise valid proof ID collides with internal snapshot state. Its error and roll-up reporting also omit required contract information on specific paths.

Full review comments:

- [P1] Keep the sandbox outside the source root — /Users/gyulafeher/Documents/Claude_Projects/wienerdog-wt/criterion-red-harness/scripts/red-proofs.js:1565-1565
  When `TMPDIR` lies beneath `--root`—for example `TMPDIR=$PWD/.tmp npm run red-proofs`—the wrapper preserves that placement and this call creates the sandbox inside the source tree. The snapshot destination then becomes a descendant of the tree being copied, causing `fs.cpSync` to reject a self-copy (or include transient runner state) while the runner also writes into the checkout it promises only to snapshot. Validate that the canonical sandbox location is outside `--root`, as required by the [snapshot/copy invariant](docs/specs/WP-criterion-red-harness.md#L287-L289).

- [P2] Isolate proof IDs from the snapshot namespace — /Users/gyulafeher/Documents/Claude_Projects/wienerdog-wt/criterion-red-harness/scripts/red-proofs.js:1360-1361
  A valid proof ID of `snapshot` makes `parent` equal `ctx.snapshot`; the first phase therefore tries to copy the snapshot into `snapshot/baseline`, and the `finally` block subsequently deletes the shared snapshot. The proof returns `ERROR` despite satisfying [Table A's unrestricted kebab-slug ID contract](docs/specs/WP-criterion-red-harness.md#L183); place proof working directories under a separate namespace or explicitly reserve this name.

- [P2] Route argument errors through the normal report — /Users/gyulafeher/Documents/Claude_Projects/wienerdog-wt/criterion-red-harness/scripts/red-proofs.js:1690-1693
  For malformed direct invocations such as `node scripts/red-proofs.js --bogus`, this catch prints only a bare usage error and bypasses the structured `ERROR` verdict and REACH footer. That contradicts [criterion 10's requirement that every green or red run end with the footer](docs/specs/WP-criterion-red-harness.md#L868-L870), so parse failures should be rendered through the same reporting path as other LOAD errors.

- [P2] Retain the declaration purpose in failed reports — /Users/gyulafeher/Documents/Claude_Projects/wienerdog-wt/criterion-red-harness/scripts/red-proofs.js:1607-1610
  When a proof is `FAILED`, `ERROR`, or `UNCONTROLLED`, `r.note` contains only the phase diagnostic, and the result/criterion roll-up retains only the ID and verdict; consequently `proof.why` disappears from the report. This violates [Table A's requirement that `why` be printed in the roll-up](docs/specs/WP-criterion-red-harness.md#L186), precisely when readers need both the proof's purpose and its failure reason.
