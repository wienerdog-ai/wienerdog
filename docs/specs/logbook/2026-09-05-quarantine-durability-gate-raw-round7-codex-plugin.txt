Findings:
- [high] Band A: same-inode modification bypasses the final gate (docs/specs/WP-quarantine-preserve-durability.md:1407-1417)
  The prescribed success expression compares bytes, completes every flush, and only then checks `(dev, ino)`. A deterministic adversary can patch the final `lstatSync(dest)` seam to overwrite `dest` in place before returning the real stat. The pathname still names the same regular inode, so `ownsName` passes and the function reports SUCCESS with the old `readBack`, while the artifact contains different bytes written after F1–F3 and never covered by a completed artifact flush. Writing before F1 similarly allows success over flushed but unverified bytes. QPD-5 covers pathname replacement, deletion, symlinks, and doctored stats—not content mutation of the same inode—so all declared evidence can pass. This falsifies F0/F1 and the closing guarantee for the expressly in-scope user's hand. Node 18 documents `fsyncSync` only as a flush request for the descriptor; it does not exclude later writes: https://nodejs.org/download/release/v18.0.0/docs/api/fs.html#fsfsyncsyncfd
  Recommendation: Add a QPD case that overwrites `dest` in place during the final `lstatSync` gate. Then either introduce a post-flush descriptor read/compare and explicitly disclose the remaining write-after-final-read window, or narrow and price same-inode concurrent modification as a residual. The current identity-only gate cannot support the stated user-hand guarantee.
