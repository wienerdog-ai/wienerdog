  3. opts.probe is an untyped public bypass of the uninstall gate.
     File: docs/specs/WP-scheduler-mutation-home-authority.md:322 (lines 322–339, 533–536)
     Scenario: any in-process caller can invoke run(argv, {probe: fakeClean}). The contract specifies neither the probe signature nor its
     result taxonomy, validation, arguments, synchronous behavior, or treatment of throws/malformed results. It only asserts that the
     current binary omits the option.
     Impact: production callers or future refactors can accidentally bypass Table U, while tests merely encode whichever interpretation the
     implementer chose.
     Recommendation: specify the exact probe interface and require throws, rejected promises, and malformed results to become NOT-PROBEABLE.
     State that no production caller may provide it and add a call-site assertion covering bin/ and src/; preferably expose a clearly test-
     only wrapper rather than extending the production run() contract.

  4. Ignoring the test guard makes forgotten seams non-hermetic—and not reliably loud.
     File: docs/specs/WP-scheduler-mutation-home-authority.md:324 (lines 324–339)
     Scenario: the suite-wide WIENERDOG_TEST_NO_REAL_SCHEDULER is set, but a test forgets opts.probe. On a clean CI machine the real query
     answers empty, uninstall proceeds, and the test silently passes; on a maintainer machine it aborts. The stated “loud, machine-
     dependent” behavior is therefore only conditionally loud.
     Impact: unit results depend on host scheduler state, and missing injection can remain undetected until run on a machine with live
     registrations.
     Recommendation: when the test guard is set and no seam was injected, throw a dedicated “test must inject probe” error before querying.
     This does not silence the safety gate or convert the domain to CLEAN; it makes forgotten injection deterministically fail.

  5. The Linux-only workflow placement is not validly specified.

     Scenario: the spec requests one env: declaration “only on the Linux leg” using if: runner.os == 'Linux'. GitHub Actions cannot attach
     if to one environment entry; putting it on the existing smoke step skips that entire step on macOS.
     Impact: a literal implementation removes the macOS CLEAN leg and defeats the claimed hard CI guarantee.
     Recommendation: prescribe a conditional value on the shared step, for example WIENERDOG_SMOKE_ALLOW_UNPROBEABLE: ${{ runner.os ==
