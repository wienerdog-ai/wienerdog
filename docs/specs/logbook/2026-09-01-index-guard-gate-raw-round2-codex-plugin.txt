- [high] [A] `--show-toplevel` is not always the frame Git uses for a relative index (docs/specs/WP-index-guard-residuals.md:75-99)
  Materiality A. Table A universally equates the worktree top with the relative `GIT_INDEX_FILE` base, but the call contract does not constrain other Git environment variables. On Git 2.39.5, with `GIT_DIR=<repo>/.git`, `GIT_WORK_TREE=/tmp`, cwd `<repo>/src`, and `GIT_INDEX_FILE=../inside.idx`, `rev-parse --show-toplevel` returned `/private/tmp`, while Git's own absolute `--git-path index` reported `<repo>/inside.idx`, inside the working tree. A locator that omits the invocation environment returns `<repo>` and also resolves `../inside.idx` outside. Thus either plausible implementation can admit a private index Git resolves inside the tree. The three standard fixture layouts do not exercise this environment-sensitive setup path.
  Recommendation: Replace the worktree-top premise with an out-of-seam query for Git's effective absolute index path using the pinned Git and the invocation environment, and measure its index safety. Add the demonstrated `GIT_DIR`/`GIT_WORK_TREE` plus `..` vector to the required evidence.
- [medium] [B] Ordinal identity check can certify a marker attached to the wrong shape (docs/specs/WP-index-guard-residuals.md:445-468)

  Recommendation: Derive module identity from physical entry order, independently verify the row labels form the exact ordinal sequence with no duplicates or decoys, then compare markers by physical position. Require a label-swap or decoy-ordinal RED.
