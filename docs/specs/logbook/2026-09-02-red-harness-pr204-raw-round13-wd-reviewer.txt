### My two attacks

**Removing `NODE_OPTIONS` whole — nothing the suite needs.** Nothing in `tests/run.js`, `tests/with-temp-root.js` or `package.json` references either variable, and the adopted lane reaches PROVEN. The residual is worth one line: a developer with an ambient `NODE_OPTIONS` (say `--max-old-space-size`) gets `npm test` running with it and phases running without, so a phase could fail where the outer suite passes. ### Two findings, both Band C

**1. [quality] The enforcement probe treats *any* write failure as proof of enforcement — `scripts/red-proofs.js:161-171`. Disposition: fix (~1 line).**

```js
try { fs.writeFileSync(child, 'x'); } catch { enforced = true; }
```

Stubbing a non-enforcing mount whose write fails for an unrelated reason:

```
probe verdict on a non-enforcing mount whose write fails ENOSPC: >>> "ENFORCED" (code not checked)
control, real host:                                              enforced (correct)
```

The error code is never inspected, so `ENOSPC`/`EDQUOT`/`EIO` on a mount that does *not* enforce mode bits reads as enforcement and the lane proceeds with inert locks. The window is narrow — it needs an exotic non-enforcing filesystem *and* a transient non-permission write failure, and `mkdtempSync` catches the common cases (`EROFS`, most `ENOSPC`) by refusing first. But the direction is permissive, in a guard whose whole job is to decide whether the lane's safety mechanism is real, and every other decision in this runner fails closed. Requiring `EACCES`/`EPERM` before concluding enforcement — and refusing with the code named otherwise — matches the file's own idiom (`assertCompleteRun` checks specific statuses; the traversal fixture matches `/EACCES|EPERM|EROFS/`).

**2. [quality] `R13-e` survives — the filesystem-root barrier guard is untested. Disposition: disclose or drop.**

Removing `path.dirname(c) !== c` leaves the suite at 135/0. I checked reachability rather than assuming: a `/` barrier needs `--root /` or `INIT_CWD=/`, and I confirmed the sandbox-inside-root check does **not** fire for `root = "/"` (`"/private/var/…".startsWith("//")` is false), so it isn't screened out earlier — but `buildManifest` walking `/` would hit a device or socket long before `PATH` mattered. And removal fails **closed**: a `/` barrier empties `PATH`, suites lose `git`/`sh`, and BASELINE goes red. So this is a usability guard against a bogus input, not a safety guard — the same unreachable-fail-safe family as `M12`, `M29` and `M50`, and it belongs in that disclosed list rather than being left implicit.
