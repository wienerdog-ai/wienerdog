### The blocking finding

**[contract] `phaseEnv` redirects `PWD` but leaves three more variables naming the real checkout — `scripts/red-proofs.js`, `phaseEnv`. Band A. Disposition: fix.**

The coordinator asked whether `INIT_CWD` is inherited and names the real checkout. It is, and so do two others. Under `npm run red-proofs` — **the documented entry point** (Table D) — four variables name the checkout, and the round-10 fix addresses one:

```
PWD                     INSIDE the copy      ← fixed this round
OLDPWD                  <removed>            ← fixed this round
INIT_CWD                >>> NAMES THE REAL CHECKOUT <<<
npm_config_local_prefix >>> NAMES THE REAL CHECKOUT <<<
npm_package_json        >>> NAMES THE REAL CHECKOUT <<<
```

The runner mentions none of the three. This is exploitable, and I demonstrated it rather than inferring it — a fixture whose suite writes `${VAR}/SENTINEL-${VAR}` for each of the three, with `INIT_CWD`/`npm_config_local_prefix` set as npm sets them:

```
verdict=PROVEN  exit=0
SOURCE TREE before: bin,subject,tests
SOURCE TREE after : SENTINEL-INIT_CWD,SENTINEL-npm_config_local_prefix,bin,subject,tests
>>> LEAKED into the source tree
```

Note the clean A/B inside one run: `SENTINEL-PWD` is **absent** because PWD is now redirected; the two unfixed variables leaked. And the run reported **PROVEN, exit 0** — a silent containment breach, where the PWD version at least reddens its fixture.

This is the same class the round graded A, on the same invariants: Table B rows 2/2a (the runner's only write into any tree is the declared mutation, into a copy) and row 2b (no two phases share a writable path the runner provides — all three variables hold an identical value in BASELINE, RED and CONTROL). It also makes the shipped REACH footer overstate: *"Each phase's **working directory**, TMPDIR/TMP/TEMP, HOME and the four XDG roots live INSIDE that phase's own copy"* — three variables that name a working directory do not.

**No current proof is affected**: the adopted suite reads none of these, the lane is PROVEN, and the checkout is byte-identical across real runs. This is a latent hole in the provided set, not an active corruption.

**Recommended fix, mirroring the precedent this spec already set.** Treat the npm-provided cwd-naming names the way row 2b treats `OVERRIDE_VARS`: a named constant in the runner, removed from (or redirected into) each phase environment, with the runner's own suite asserting the constant still covers what `npm run` actually sets — the criterion-8b drift-check shape. Removal is the simpler option and matches Decision 1's precedent. The `suite-pwd.js` fixture extends to cover them with a few lines.

**One spec-side note for wd-architect (Band C, non-blocking):** row 2b enumerates the provided set by name, and "the working directory" has now twice turned out to have members nobody had enumerated (`PWD` this round, these three now). The cell would be more durable stated as a *property* — no environment variable handed to a phase may name a path outside that phase's copy — with the enumeration as the current instance. That is the same move round 2 made when it withdrew the universal containment claim in favour of a checkable one.
